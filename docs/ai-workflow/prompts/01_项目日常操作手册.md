# 项目日常操作手册（人类 Prompt Playbook / Recovery）

> **权威范围**：本文件是仓库内「人类日常如何粘贴 / 恢复 / 失败处置」的**唯一权威 Playbook**。  
> **职责分离**：`01_初始化与Backlog.md` 是 AI/角色向的「初始化与 Backlog」Prompt；**本手册 ≠ Backlog Prompt**，二者文件名均以 `01_` 开头但读者与用途不同，不得互相替代或合并正文。  
> **不改** `00_全局开发规则.md`：AI 固定约束与 Mihomo §18 仍以该文件为权威；本手册只引用，不复制 secrets。

## 我以后只需要记住什么？

即使忘记全部会话历史，也只需记住下面最小清单即可继续本项目：

1. 打开 `02_开发管理/progress.md` 与当前 Task Plan，确认 `current_task` / `status` / 分支。
2. 从本手册选择**一个**英文模板 ID，复制粘贴块填空后发给 Orchestrator。
3. **NORMAL 常规人工门禁恰好两扇**：① 人工 `PLAN_APPROVED`；② 人工 Human PR Merge。  
   **`READY_FOR_HUMAN_COMMIT` 不是第三扇常规人工门**（仅为 Commit Recorder 兼容边界标记）。
4. 编码前必须有已批准 Task Plan；禁止根据短描述发明实现。
5. 永久禁止危险 Git：`gh pr merge`、`git push --force` / force push、`git reset --hard`、`git clean -fd`、`git branch -D`。
6. 失败时先只读分类；**fix ≠ retry**；禁止盲目重试；禁止把「允许修代码」解释成「允许重跑受保护命令」。
7. Mihomo / Docker 细节只查 `docs/ai-workflow/prompts/00_全局开发规则.md` §18，不猜代理、不提交 Secret。

## NORMAL vs STRICT（SHOULD_FIX 1）

| 模式 | 常规人工门 | 自动串联 |
|---|---|---|
| **NORMAL** | 恰好两扇：人工 `PLAN_APPROVED` + Human PR Review/Merge | 人工 `PLAN_APPROVED` 后，可按成功 marker **自动串联** Subagent / Release phase（`PLAN_LANDING`→Developer→tests→Code Reviewer→Commit Recorder→`IMPLEMENTATION_RELEASE`→push/PR→`WAITING_FOR_PR_MERGE`）；Merge 后自动 `POST_MERGE_CLEANUP`。无第二次手工 `PLAN_LANDING` 门；`READY_FOR_HUMAN_COMMIT` 后自动 `IMPLEMENTATION_RELEASE` |
| **STRICT** | **保持详细人工 gate**（含显式 Release 等既有门禁） | **不得**因 NORMAL 规则自动串联下一角色 / Release phase；**不改变**现有 STRICT 语义 |

选择模式：粘贴块中写明 `WORKFLOW_MODE=NORMAL` 或 `STRICT`，并注明 source（`explicit` / `default`）。缺省行为以编排契约为准（默认 NORMAL），但人类应显式写出以免歧义。

## 六模板（可直接复制）

每个模板标题即英文 ID（可检索锚点）。粘贴前核对 `progress.md` / 当前 Task Plan / `git status` / 当前分支。

### START_EXISTING_TASK

**用途**：从干净或已知状态继续**已登记**任务。  
**硬约束（MF-2）**：首轮 **planning-only**——Orchestrator 只调度 Planner→Plan Reviewer→等待人工 `PLAN_APPROVED`；**禁止**根据人类短描述发明实现；实施内容须从仓库权威源（`progress.md` / 当前 Task Plan / 规格 / 既有代码）推导。

**前置**：仓库可访问；已知或可从 progress 读出 `TASK_ID`。  
**下一步**：等待独立 Plan Review → 人工 `PLAN_APPROVED`（勿跳到 Developer）。

```text
TEMPLATE: START_EXISTING_TASK
TASK_ID: <e.g. DEV-OPS-005>
WORKFLOW_MODE: <NORMAL|STRICT>
workflow_mode_source: <explicit|default>

首轮 planning-only：只允许 Planner → Plan Reviewer → 等待人工 PLAN_APPROVED。
禁止从人类短描述发明实现；须从仓库权威源推导任务内容。

权威源核对清单：
- [ ] 02_开发管理/progress.md（current_task / status / branch）
- [ ] 当前 Task Plan 路径与 status
- [ ] git status（工作树是否干净）
- [ ] git branch --show-current
```

### PLAN_APPROVED

**用途**：人工确认计划批准后的续跑口令（NORMAL **常规人工门禁 #1**）。  
**硬约束（MF-1 / MF-3）**：其后 **NORMAL 自动链**（无第二次手工 `PLAN_LANDING` 门）：

```text
PLAN_LANDING
→ Developer
→ tests
→ Code Reviewer
→ Commit Recorder（输出 READY_FOR_HUMAN_COMMIT）
→ IMPLEMENTATION_RELEASE（自动；push/PR）
→ WAITING_FOR_PR_MERGE
```

`READY_FOR_HUMAN_COMMIT` = Commit Recorder 兼容边界标记，**非**第三扇常规人工门；NORMAL 在该标记后**自动**进入 `IMPLEMENTATION_RELEASE`。NORMAL 下实现 Commit/PR 由 Release Operator 自动执行（非人类手工 `git commit` 门禁）。Code Reviewer / Commit Recorder / `IMPLEMENTATION_RELEASE` 在 NORMAL 下正常自动串联（fail-closed 例外除外）。

```text
TEMPLATE: PLAN_APPROVED
TASK_ID: <e.g. DEV-OPS-005>
PLAN_APPROVED

确认计划文件：
02_开发管理/tasks/<TASK_ID>-<slug>.md

WORKFLOW_MODE: <NORMAL|STRICT>
说明：NORMAL 下本口令后自动 PLAN_LANDING→…→WAITING_FOR_PR_MERGE；无第二次手工 PLAN_LANDING 门。
STRICT 下保持详细人工 gate，不得按 NORMAL 自动串联。
```

### AFTER_PR_MERGE

**用途**：人工 Merge PR 之后恢复编排（NORMAL **常规人工门禁 #2**）。  
**硬约束**：PR Merge **永远人工**；禁止 Agent 执行 `gh pr merge`。验证 MERGED / base / head / merge SHA / **clean 工作树** 后，NORMAL 期望自动 `POST_MERGE_CLEANUP`（无需第三次批准门）。进入或恢复 `WAITING_FOR_PR_MERGE` 前工作树必须干净（或仅含已批准白名单内预期变更）；unexpected dirty → fail-closed。

```text
TEMPLATE: AFTER_PR_MERGE
TASK_ID: <e.g. DEV-OPS-005>
PR: <#N>
merge 证据：已人工 Merge（state=MERGED；记录 merge SHA / base / head）

已人工 Merge；禁止 Agent 执行 gh pr merge。
请在验证 MERGED + clean working tree 后执行 NORMAL 自动 POST_MERGE_CLEANUP。
```

### RECOVERY_MODE

**用途**：会话丢失 / 状态不明。  
**硬约束**：先只读核对再决定；**无 Git 写、无实施**；冲突或不明 → fail-closed。slow command 不得触发重复并发执行。

```text
TEMPLATE: RECOVERY_MODE
TASK_ID: <若已知则填写；未知则写 unknown>

先只读：禁止 Git 写、禁止实施、禁止盲重试。
核对清单：
- [ ] 02_开发管理/progress.md
- [ ] 当前 Task Plan status / approval_gates
- [ ] git status / git branch --show-current
- [ ] 最近 commit / PR 状态（只读）

冲突或不一致 → fail-closed；报告后等待人类指示。
```

### NEW_UNPLANNED_FEATURE

**用途**：未规划新需求。  
**硬约束**：先判定归属（已有 Task / 新 Task / 规格变更）；**先规划**（Task Plan → Plan Review → `PLAN_APPROVED`）；**禁止立即编码**；禁止跳过规格冲突报告。

```text
TEMPLATE: NEW_UNPLANNED_FEATURE
需求短名: <短名>
WORKFLOW_MODE: <NORMAL|STRICT>

先判定归属 / 是否需要新 Task / 是否触及规格。
先规划、禁止直接编码；未获 PLAN_APPROVED 不得编写业务代码。
```

### FAILURE_AND_RECOVERY

**用途**：失败分类与恢复。  
**硬约束**：**fix ≠ retry**（修复权限 ≠ 重试权限）；fail-closed 后不得把「允许修代码」解释成「允许重跑受保护命令」；禁止盲目重试同一失败命令；耗尽预算 → HALT + 报告；governance deviation 须显式记录分类（如 GD-*）；**final tests PASS ≠ workflow compliance**。

```text
TEMPLATE: FAILURE_AND_RECOVERY
TASK_ID: <若已知>
失败现象摘要: <一句话>
已尝试步骤: <列表>
分类码（若已知）: <e.g. PROXY_DOWN | GD-* | unknown>

声明：fix≠retry；禁止盲目重试同一失败命令。
fail-closed 后：允许修代码 ≠ 允许重跑受保护命令。
请先只读分类，再给出有界下一步（或 HALT）。
```

## 规则 A–E

### 规则 A（no blind retry）

禁止盲目重试同一失败命令。先分类再行动；重试预算有界；预算耗尽 → HALT + 报告人类。slow / hung 命令不得叠加并发重复执行。

### 规则 B（Docker / Mihomo）

网络与 Docker 代理细节**引用**权威文件：`docs/ai-workflow/prompts/00_全局开发规则.md` §18（DEV-OPS-004），**不**在本手册全文复制策略或 secrets。

必须记住的对照（细节以全局规则为准）：

- Docker **daemon** 代理 ≠ BuildKit / 临时 ad-hoc RUN proxy；不得给 `docker` / `compose` 临时注入代理绕过策略。
- 端口 `7890` ≠ Mihomo（`7890` 为 SSH forwarding）；本机 Mihomo mixed = `127.0.0.1:17890`。
- 不得猜测 container→host proxy；host-specific workaround **不得**污染通用部署 / 规格 Contract。

### 规则 C（self-ref SHA）

禁止把「即将产生的自身 commit SHA」当成已存在事实。`latest_commit` / 治理字段须为**真实已存在** HEAD，或明确 `null` / 待填。self-referential Git commit SHA **不可稳定实现**。

### 规则 D（WAITING clean）

进入或恢复 `WAITING_FOR_PR_MERGE`（及同类 pause）前，工作树须干净（或仅含已批准白名单内预期变更）。unexpected dirty → fail-closed。

### 规则 E（governance deviation）

发现治理偏差须显式记录分类（如 GD-*）。接受偏差 ≠ 放宽 fail-closed；未来失败仍须报告 + 授权。不得用 deviation 掩盖盲重试。**final tests PASS ≠ workflow compliance**——测试全绿不能替代治理合规。

## Operational invariants（摘要）

| ID | Invariant |
|---|---|
| MF-1 | NORMAL 常规人工门禁**恰好两扇**：`PLAN_APPROVED` + Human PR Merge；`READY_FOR_HUMAN_COMMIT` **不是**第三扇常规人工门 |
| MF-2 | `START_EXISTING_TASK` 首轮 planning-only；禁止短描述发明实现；从权威源推导 |
| MF-3 | 人工 `PLAN_APPROVED` 后 NORMAL 自动链至 `WAITING_FOR_PR_MERGE`；无第二次手工 `PLAN_LANDING` 门 |
| AUTO | NORMAL 下 Code Reviewer / Commit Recorder / `IMPLEMENTATION_RELEASE` 正常自动串联 |
| MERGE | PR Merge 永远人工；禁止 Agent `gh pr merge`；Merge 后 NORMAL 自动 `POST_MERGE_CLEANUP` |
| REC | Recovery 先只读；无 Git 写 / 无实施；冲突 fail-closed |
| RETRY | 禁止盲目重试；fix≠retry；fix permission != retry permission |
| PROXY | daemon proxy ≠ BuildKit RUN proxy；7890 ≠ Mihomo；不猜 container→host proxy；host workaround 不污染通用部署 |
| SHA | self-referential commit SHA 不可稳定实现 |
| WT | `WAITING_FOR_PR_MERGE` 前工作树必须 clean |
| GOV | final tests PASS ≠ workflow compliance；governance deviation 须显式记录分类 |
| SECRET | 禁止提交 Secret / 真实用户数据 |
| BAN | 永久禁止：`gh pr merge`、force push / `--force`、`reset --hard`、`clean -fd`、`branch -D` |
| MODE | STRICT 保持详细人工 gate；不得因 NORMAL 规则自动串联；不改变现有 STRICT 语义 |
