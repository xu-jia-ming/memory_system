# Task Development Prompt

```text
任务 `{TASK_ID}` 的 Task Plan 已获得 `PLAN_APPROVED`。

严格按照：

`02_开发管理/tasks/{TASK_ID}-{TASK_SLUG}.md`

实施。

开始前：

1. 确认计划状态为 approved；
2. 检查 git status；
3. 确认当前任务分支；
4. 更新计划状态为 in_progress；
5. 更新 progress.md。

开发规则：

1. 只实现当前任务；
2. 只能修改计划文件变更清单中的文件；
3. 需要修改清单外文件时，先新增 Plan Amendment 并停止等待批准；
4. 不得改变 API、Schema、错误码、状态机、依赖和技术选型；
5. 不得使用 TODO、pass、空实现或 Mock 业务结果；
6. 业务代码和测试必须一起实现；
7. 每完成一个主要步骤，更新 Task Plan 的执行记录；
8. 记录实际文件和与计划的差异；
9. 测试失败时继续修复；
10. 不得删除断言、跳过失败测试或扩大容差。

实现完成后：

1. 状态改为 implemented；
2. 运行计划规定的所有测试；
3. 运行 Ruff；
4. 运行 Mypy；
5. 将命令和结果写入 Task Plan；
6. 全部通过后状态改为 tested；
7. 更新 progress.md；
8. 输出 git diff --stat 和修改摘要；
9. 不执行 Commit；
10. 停止，等待独立 Code Review。
```
